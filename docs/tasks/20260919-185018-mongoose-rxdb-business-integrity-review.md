### Task RMRX-01: Preserve Data When Saving Partial Documents

Status: completed

Kind: defect

Priority: P0; changing a redacted array can silently erase stored hidden fields.

Suggested agent: projected document persistence specialist

Dependencies: none

Primary ownership: `src/document.ts`, `src/query.ts`, relevant hydration/types in `src/model.ts`, projection/default save regression tests, README/website contract notes (all paths under package unless specified).

Additionally `toObject()` omits undefined while snapshots retain it, and `changedLeafValues` applies defaults to both (`document.ts:187-193,392-408`), potentially synthesizing an undefined update for projected-out defaults or default-disabled upserts. Existing `projection-boundary.test.ts:94-124` and `default-recursion-boundary.test.ts:99-155` stop before subsequent save. Residual intersection of MRX-08/10 and BMRX-02/08/13.

Preserve unseen values or reject unsafe replacement of incomplete subtrees before writes; never guess array identity or silently remove hidden data. ### Task RMRX-04: Preserve Dirty Intent Across In-Flight Saves

Status: completed

Kind: defect

Suggested agent: document lifecycle/concurrency specialist

Dependencies: RMRX-03

Primary ownership: `src/document.ts`, save concurrency tests and public errors/types if needed, README/website.

Finding: save captures data, awaits storage, then clears all dirty intent (`document.ts:245-276`). Assigning a parent object during that await loses its replacement marker; a second save merges leaves and may retain unseen fields that replacement should remove (`document.ts:399-407,775-791`). Existing snapshot/nested tests cover failure/retry or separate documents, not mutation during one save. Residual MRX-08/BMRX-08.

Requirements: clear only intent captured by a successful save using generations or an equivalent precise mechanism. Preserve changes made during persistence and failure retry behavior. Define overlapping saves on the same instance with deterministic rejection or serialization; do not allow completion-order snapshot corruption. Any new public error must be exported with declaration/consumer evidence.

Acceptance criteria: gated tests cover scalar edits, explicit parent assignment/set/markModified during persistence, unchanged repeated path markings, failed save then retry, new-record saves, and overlapping save calls. Later replacement intent survives and full second-save storage reflects it; no duplicate insert or stale snapshot completion occurs. Hooks retain once-per-operation error/success semantics.
