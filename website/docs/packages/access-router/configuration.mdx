# Configuration

Configuration has separate layers: runtime `GlobalOptions`, shared model starting
defaults, per-model/data/root options, model per-method `defaults`, request `args`/
`options`, and trusted service `authorization`. Data/root routers do not inherit model
defaults; authorization is never a default or wire option. `createAccessRuntime()`
returns a bound API whose `.runtime` owns the options and registries.

## Global Options

Configure a runtime with `acl.setGlobalOptions(...)` or the corresponding isolated
API method. Assignment is shallow. Request initialization and hook/persistence
captures are not restarted by later setters.

- `requestPermissionField` defaults to `_permissions`
- `globalPermissions(req)` returns the permission set for the current request
- `logger` receives `debug`, `info`, `warn`, and `error` calls

<!-- doc-example: partial -->

```ts
import acl from '@web-ts-toolkit/access-router';

declare module '@web-ts-toolkit/access-router' {
  interface AccessRouterRequestExtensions {
    actor?: { permissions: string[] }; // set by application authentication middleware
  }
}

acl.setGlobalOptions({
  requestPermissionField: '_permissions',
  globalPermissions(req) {
    return req.actor?.permissions ?? [];
  },
});
```

Null/undefined resolver results establish empty grants, replacing prior runtime-owned
values. Application-supplied unowned maps are preserved; same-runtime middleware
reuses its initialized state. Populate targets always require actual runtime model
registration and an effective object `permissionSchema`. See the independent
[populate operation policies](#populate-operation-policies).

## Default Model Options

These values supply model defaults. Assignment is shallow; nested rule objects
are not recursively merged. See [Operation access](#operation-access) for exact
variant/default lookup and live updates.

- `listHardLimit` defaults to `1000`
- `documentPermissionField` defaults to `_permissions`
- `idParam` defaults to `id`
- `idField` defaults to `_id`
- `parentPath` defaults to `/`
- `queryRouteSegment` defaults to `__query`
- `mutationRouteSegment` defaults to `__mutation`
- `operationAccess` defaults to `false`
- `modelPermissionPrefix` defaults to an empty string
- `requireOperationAccessForPopulateQueries` defaults to `true`; only primitive `false`
  bypasses the actual target's ordinary effective read/list/trusted custom admission
- `requireOperationAccessForPopulateDependencies` defaults to `true`; only primitive
  `false` bypasses the actual target's private base-read operation gate

Model options inherit live defaults without being copied into permanent model overrides.
Each populate flag resolves explicit target override → captured runtime model default →
true. Explicit undefined restores inheritance; omission retains an override. Nested
option objects replace shallowly.

Include output cannot equal, descend from, or contain `documentPermissionField`,
including dotted custom fields and equivalent legacy bracket paths. Nested include
levels use the receiving model's setting; violations are BadRequest before target
persistence. See [Services](./services#safe-include-output-and-exact-counts).

### Authority, hook inputs and metadata

Router `defaults`, including dotted setters, contain query/presentation settings only.
Per-call service authorization, document handles, prepared/execution state and removed
service overrides are not defaults or HTTP/OpenAPI/client options. Supply trusted
server-only policy to the service acquired from `router.getService(req)` instead.
Missing policy dimensions use request authority and never inherit a prior call's elevation.

`alwaysSelectFields` declares persisted inputs needed by document-permission hooks beyond
selected output, such as `ownerId`. Hooks see the untrimmed projected document; fetch-only
inputs do not grant output. The immutable call captures configuration, while each document/
scope/access stage has separate hook grants and decisions. Opaque result-context handles
preserve them after those inputs and metadata trim. See [Services](./services#call-policy-and-document-result-reuse).

Internal document grants resolve independently of `includePermissions`,
`includeFieldPermissions`, `stripPermissionsField`, `disableFieldPermissions` and exposed-key
limits. These switches govern request-user metadata serialization; temporary backend grants
never forge `_view`/`_edit`. `overrideFilter` remains the query-transform hook and runs once
even in unrestricted row mode; scope/unrestricted replace only `baseFilter` authority.

`skim` is a deprecated compatibility no-op in canonical model operations. True, false
and omission all retain authorization, document grants, virtuals and decoration.
Server model `hydration` separately chooses Mongoose materialization; there is no
per-call/wire `lean` or `hydration` control, and field enforcement always runs.

At each method resolver, non-nullish supplied values win over its `defaults` bucket,
then built-ins. Public wrappers resolve `public*Args`/`public*Options` before internal
methods; already-resolved flags take precedence over internal defaults. Public upsert
uses its create/update branch's public bucket. A model service captures current presentation
defaults from its originating runtime per call; per-call model authority captures current
policy before awaiting hooks. Retained services keep their original core, actor, model
connection and related registry across a same-request runtime handoff. Base-filter cache
entries are reused only for the same model/access and policy function.
Request base-filter caches remain owned by their request/runtime/access.

### Temporary unsafe read/list-performance switches

The original six comparison/two initial-copy contracts below retain their copy/graph
guarantees only with the matching new authorization fast-path flag **OFF (or dormant)**.
The separately opted-in active mode described below deliberately weakens them.

Model-only `unsafeSkipListDocumentSnapshotChecks: true` skips repeated source snapshot
comparisons on top-level `find`, generated lists and root-list entries. Independent
`unsafeSkipReadDocumentSnapshotChecks: true` does the same for `findOne`, `findById`,
public identifier/filter reads and root reads.

Four further independent flags are available:

| LIST                                         | READ                                         | Skips                                                                     |
| -------------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------- |
| `unsafeSkipListOutputSnapshotChecks`         | `unsafeSkipReadOutputSnapshotChecks`         | Output-value comparisons for root and embedded/populated/included outputs |
| `unsafeSkipListNestedDocumentSnapshotChecks` | `unsafeSkipReadNestedDocumentSnapshotChecks` | Source comparisons on embedded/populated/included document stages         |

Read-to-list retries follow all three **READ** settings, not LIST settings. All six
default to `false`, are captured before awaits, and warn independently on enablement.
Configure them with `api.setModelOption` or
`api.setDefaultModelOptions`; unspecified model flags inherit later default updates,
including after router creation. Explicit per-model `false` wins over default `true`;
model `undefined` restores inheritance. This precedence applies to all model-default
options; object/array overrides replace shallowly. Restore `false` for new calls as soon as possible. Never
derive these flags from request input.

Inherited enablement warns once per effective model/flag transition, just like an
explicit model setter. Defaults configured before model setup warn when applied to
that model. Existing call/handle snapshots and mounted route paths do not change.

Output/nested settings propagate recursively from the **initiating model**, not the
target model's flags. Root-source, nested-source and output-value checks are independent;
nested flags do not prune child values from still-strict parent comparisons.

Permission rules, exact associations/bindings, output graph identities and initial
snapshots/detached copies remain with the new copy flags below off. Writes, dedicated subdocument operations and fresh
helpers stay strict. Originating handles, captured retries and later descendants
retain their original mode after rollback. **Source mutation can leave stale grants/
decisions; output flags additionally allow changed values with unchanged identities
to reuse authorization and expose incorrectly authorized data.** Use only as a
temporary, measured workaround, not as a security-equivalent fast path. Per-call,
wire and method-default controls cannot enable it. See the shipped README for the contract.

#### Separate initial output-copy opt-outs

`unsafeSkipListInitialOutputSnapshotCopy` and `unsafeSkipReadInitialOutputSnapshotCopy`
are two additional server model/default booleans, **false by default**. Each requires
its matching `unsafeSkipListOutputSnapshotChecks` / `unsafeSkipReadOutputSnapshotChecks`
to be true. Copy true with comparisons strict is **dormant**: copying/comparisons stay
on and a prerequisite warning is logged. Neither option silently changes another flag.

When active, eligible initial output-association snapshots (including authenticated
embedded/populated/included outputs and package-created transfers) are omitted. READ
retries keep READ settings; targets cannot override the initiating model. Inheritance,
literal-true enablement, server-only controls and captured-handle rollback match the
comparison flags. Active/dormant warnings follow effective model/operation transitions,
not rows/requests. Writes, dedicated subdocument operations and fresh helpers stay strict.

**Additional risk:** this pass no longer clones/normalizes native leaves or runs BSON
wire-validation hooks. Changed observations can alter exceptions, side effects and
permission outcomes—even turn denial into allowance. Ordinary graph admission retains
safe keys/descriptors, cycles, 20,000 visited-node/array-length and depth-100 limits,
plus exact graph/binding ownership. Standard native leaves are admitted without this
normalization; invalid/forged BSON content is not wire-validated by the omitted pass.
Proxies, Map/Set, unproven subclasses/unsupported graphs use the original copy fallback.
Accessor/proxy ownership bindings also fall back, rather than retaining graph admission
across binding callbacks.

Source snapshots, detached callback inputs/grants, configuration, getters, metadata
and actual response-copy boundaries remain. This is not an all-cloning opt-out and
does not promise historical performance. Prefer temporary per-model opt-in only after
reviewing trusted data/hooks and measured rollout evidence. Restore the copy flag to
false and then restore strict comparisons for new calls; retained authority keeps its
captured mode. The [shipped README](https://github.com/egose/web-ts-toolkit/blob/main/packages/access-router/README.md#temporary-unsafe-initial-output-snapshot-copy-switches)
contains the four-combination table and server-only example.

### Experimental unsafe READ/LIST authorization fast paths

`unsafeUseListAuthorizationFastPath?: boolean` and
`unsafeUseReadAuthorizationFastPath?: boolean` form a third independent default-false
server model/default group. Literal true requests the mode; each needs **all four**
matching `unsafeSkip{List,Read}DocumentSnapshotChecks`, `OutputSnapshotChecks`,
`NestedDocumentSnapshotChecks` and `InitialOutputSnapshotCopy`. False/omitted is off;
true with any missing prerequisite is dormant with original flag behavior. Never
auto-enables prerequisites. Explicit model false overrides defaults; undefined
restores inheritance. Control-slot presence in requests/defaults/policy/helpers/
include/populate/`$$sq` rejects; same-named business data remains inert.

Capture precedes hooks/awaits on a genuine query origin. READ-to-list retries retain
READ, genuine embedded/related descendants inherit origin capture rather than live
target flags, and independent calls capture their own settings. Writes/write-derived
output, new/create/update/delete/upsert, dedicated subdocuments and fresh raw helpers
stay strict. Effective active/dormant/missing-prerequisite changes warn, not each call.

Active ordinary lean source/hook input and grants are borrowed; shallow contexts and
captured config/scope views are reused. Actual operation/row/field rules, actor,
mandatory once-per-root/target document hooks, getters and target admission remain.
Independent rows/targets do not share grants/decisions by ID. Trusted outputs have
exact root bindings and **issued-document membership, not current graph walks**:
removed original children may remain discoverable, replacements get no handle, and
root helpers filter current values with stale memo/shared grants after replacement.
Metadata/includes finish before one association; source/attachment lanes stay separate.

New selected work is bounded to 20,000 visited slots/issued roots and depth 100, with
safe descriptor writes/cycle errors—not full unvisited source/grant/context validation.
Shallow-unproven rows may use copied compatibility before hooks, exotic grants/value
fallbacks copy once, and mixed copied/trusted rows can coexist. Selected unsupported
values reject (invalid virtual returns omit). Hydration, selected natives, getter
stable-base/per-getter views/return staging, private argument-four isolation and JSON
serialization still copy/normalize. Active configuration is **not every-row zero-copy**.

Mutation/stale decisions/changed descendants/fewer native observations can turn denial
into allowance. Experimental performance-first, not a full ACL bypass, security-equivalent
optimization, publication fusion, universal gain or v0.51.0 parity. Benchmark your workload.
Rollback protects new calls only; retained trusted handles keep weaker semantics,
and original prerequisite skip flags must be restored separately. The
[installed README](https://github.com/egose/web-ts-toolkit/blob/main/packages/access-router/README.md#experimental-unsafe-readlist-authorization-fast-paths)
is authoritative and includes executable LIST/READ and retained-handle warnings.

<!-- doc-example: partial -->

```ts
import { createAccessRuntime, type DefaultModelRouterOptions } from '@web-ts-toolkit/access-router';

const api = createAccessRuntime();
const readDefaults = {
  unsafeSkipReadDocumentSnapshotChecks: true,
  unsafeSkipReadOutputSnapshotChecks: true,
  unsafeSkipReadNestedDocumentSnapshotChecks: true,
  unsafeSkipReadInitialOutputSnapshotCopy: true,
  unsafeUseReadAuthorizationFastPath: true,
} satisfies DefaultModelRouterOptions;
api.setDefaultModelOptions(readDefaults); // LIST stays independently off
api.setDefaultModelOption('unsafeUseReadAuthorizationFastPath', false);
// Existing READ retries/handles keep captured semantics. Restore other skips separately.
```

### Populate operation policies

Both optional model/default booleans have built-in true. Each actual target resolves
explicit override → captured runtime model default → true. Explicit undefined clears
an override to inherit; omission preserves it. Only primitive false disables a gate;
malformed non-undefined JavaScript values normalize conservatively to true.

For `Project.documentIds → Document`, use **Document's** Q/D, regardless of Project's
settings. A Document virtual referencing User uses **User's D**. Different pairs can
coexist for Document/User/Report in one runtime/request. Defaults are captured before
source/target option reads and the first await; each target contributes its captured
options. In-flight nested/include/embedded/dedicated-child stages retain that capture;
later calls on existing services refresh and see live defaults without an override.
Unrelated updates/router construction/repeated decorator setup do not freeze inherited
defaults. Nested option objects replace shallowly.

Use model/default bulk/exact setters and model-router setters. `GlobalOptions`,
`api.setGlobal*` and global `api.set` reject stale placements with actionable
`setModelOptions` / `setDefaultModelOptions` migration diagnostics, without aliases
or broadcasting. Query, method-default, HTTP/root/client options gain no capability.
Same-spelled business fields remain ordinary data. `getModelOptions()` and
`router.options` retain raw flag overrides; `getModelOption()` reads the live default.
An unset undefined can still resolve strictly to true during operation capture.

Every requested ordinary target and declared private target needs the actual Mongoose
model and ACL configuration in its owning runtime, with an **effective object
`permissionSchema`**. Model defaults may supply it; `{}` is a closed business-field
policy. Missing target registration/schema fails with controlled `bad_request` and
`errors[].detail` (HTTP 400) before target I/O or initiating writes. Direct helpers/
configuration setters throw with that controlled `result`; private declaration validation
is eager/atomic. Unused ordinary schema refs need not be configured at startup.

Configuration-only models need no HTTP routes:

<!-- doc-example: partial -->

```ts
import mongoose from 'mongoose';
import { createAccessRuntime } from '@web-ts-toolkit/access-router';

const api = createAccessRuntime();
const Document = mongoose.model('Document', new mongoose.Schema({ name: String, internalNote: String }));
const User = mongoose.model('User', new mongoose.Schema({ name: String }));
api.registerModelInstance(Document.modelName, Document);
api.registerModelInstance(User.modelName, User);
api.setDefaultModelOptions({
  requireOperationAccessForPopulateQueries: true,
  requireOperationAccessForPopulateDependencies: true,
});
api.setModelOptions(Document.modelName, {
  operationAccess: { read: false, list: false },
  permissionSchema: { name: true, internalNote: false },
  requireOperationAccessForPopulateQueries: false,
  requireOperationAccessForPopulateDependencies: false,
});
api.setModelOptions(User.modelName, {
  operationAccess: { read: false, list: false },
  permissionSchema: {}, // explicitly closed business fields
  requireOperationAccessForPopulateQueries: true,
  requireOperationAccessForPopulateDependencies: true,
});
// One source request can populate permitted Document fields while User stays strict.
// Neither target needs HTTP routes; standalone guarded/root target reads/lists deny.
```

Q is the target's `requireOperationAccessForPopulateQueries`; D is its
`requireOperationAccessForPopulateDependencies`. Independently for each target, with public/read operations
denied, selected/permitted source refs and otherwise eligible rows/fields:

| Q     | D     | Ordinary requested population   | Authorized private virtual    |
| ----- | ----- | ------------------------------- | ----------------------------- |
| true  | true  | Original parent IDs             | Omitted                       |
| false | true  | Selected/authorized target DTOs | Omitted                       |
| true  | false | Original parent IDs             | Computed from declared inputs |
| false | false | Selected/authorized target DTOs | Computed from declared inputs |

Q=false skips only target operation admission. Source entry/source-field permissions,
target field/document grants, row/base/transform filters, original selection and `_id`
exclusions, requested match and mandatory reference IDs remain. Direct/generated/root
target operations still enforce their own guards. Required ordinary guard errors
propagate; bypass does not call the guard. False guards deny population and leave
permitted parent IDs; actual admitted match/missing-row population yields null/filtered
arrays, not IDs. Scoped trusted related operation grants retain their separate authority.

Ordinary static string refs resolve on the source model's Mongoose connection and
must be the exact instance registered/configured in the owning runtime. Missing or
same-named mismatched models fail preflight before target reads or initiating writes.
Explicit Model-valued schema refs can cross connections when that exact target is
registered/configured in the same runtime. The validated model stays pinned with its
captured policy through in-flight work; late `db.models` substitution cannot replace
it. The public `Populate` wire gains no `model`/authority property. Private declarations
retain their narrower static-string, same-connection limit below.
Dynamic callback/refPath refs reject with a controlled diagnostic because they cannot
be statically bound before I/O.

**Removed:** `requireRegisteredPopulateModels` and
`requireReadOperationAccessForPopulateDependencies`, with no aliases/raw-mode mapping.
Register/configure targets, then choose Q/D independently; migrate an intentional
private bypass to the new dependency name at model/default scope. Previous global
placements must move to model/default setters or scoped decorators; they are rejected,
not broadcast. The former PPR whole-reference omission
rule is superseded: deny the source field if its IDs must be hidden. See the
[installed README's runnable Document example](https://www.npmjs.com/package/@web-ts-toolkit/access-router#runnable-private-dependency-example).

### Private populated virtual dependencies

Declare `dependsOnPopulate` in trusted model virtual configuration when an authorized
computed output needs related persisted fields the caller cannot receive. Local
`dependsOn` remains the current scope's persisted inputs in getter argument one;
ordinary query `populate` remains public related output. The new declaration supplies
only that getter's **fourth argument**, independently of public population.

Register the actual target model **and its options first**, in the source's runtime
and Mongoose connection. Validation is eager/atomic for construction, bulk and dotted
setters, regardless of either operation flag. Operation capture
rechecks bindings before hooks/writes; in-flight calls retain coherent getter/masks/policies.

The actual target's `ModelRouterOptions.requireOperationAccessForPopulateDependencies`
inherits `DefaultModelRouterOptions` and then built-in **true**:
private loading requires the captured original caller's target base `operationAccess.read`.
Only primitive boolean **false** bypasses that operation gate. Explicit undefined
restores inheritance, omission retains an override, and other malformed JavaScript
values are conservatively true. Configure model defaults on the owning runtime:

<!-- doc-example: partial -->

```ts
import { createAccessRuntime, type DefaultModelRouterOptions } from '@web-ts-toolkit/access-router';

const api = createAccessRuntime();
api.setDefaultModelOptions({
  requireOperationAccessForPopulateQueries: true,
  requireOperationAccessForPopulateDependencies: false,
});
api.setDefaultModelOption('requireOperationAccessForPopulateDependencies', false);
const snapshot: DefaultModelRouterOptions = api.getDefaultModelOptions();
void snapshot;
```

Model setters provide explicit target overrides; set a target flag to undefined to
inherit again. Later top-level calls on existing unoverridden models/services see
updated defaults; nested related/embedded/child stages retain their owning capture.
This is independent of the same target's `requireOperationAccessForPopulateQueries`;
registration/effective object schema and static declarations stay mandatory.
`getDefaultModelOptions()` / `getModelOptions()` return frozen raw snapshots, not
resolved effective policy; read them again for later storage changes. Named root
getters/setters use the active runtime, falling back to the shared default runtime.

<!-- doc-example: partial -->

```ts
import mongoose from 'mongoose';
import { createAccessRuntime, type ModelVirtualDescriptor } from '@web-ts-toolkit/access-router';

interface Account {
  name: string;
  balance: number;
  creditLimit: number;
  tenantId: string;
}
interface Order {
  total: number;
  account: mongoose.Types.ObjectId | null;
}
const api = createAccessRuntime();
const AccountModel = mongoose.model<Account>(
  'ConfiguredAccount',
  new mongoose.Schema<Account>({
    name: String,
    balance: Number,
    creditLimit: Number,
    tenantId: String,
  }),
);
api.createRouter(AccountModel, {
  operationAccess: { read: true },
  baseFilter: { read: () => ({ tenantId: 'example-server-owned-tenant' }) },
  permissionSchema: { name: true, balance: false, creditLimit: false },
});
const OrderModel = mongoose.model<Order>(
  'ConfiguredOrder',
  new mongoose.Schema<Order>({
    total: Number,
    account: { type: mongoose.Schema.Types.ObjectId, ref: AccountModel.modelName },
  }),
);
const canPlaceOrder: ModelVirtualDescriptor<Order, boolean, { account: Account }> = {
  dependsOn: ['total'],
  dependsOnPopulate: [{ path: 'account', select: ['balance', 'creditLimit'] }],
  get(doc, _permissions, _context, populated = {}) {
    const account = populated.account;
    if (doc.total === undefined || account?.balance === undefined || account.creditLimit === undefined)
      return undefined;
    return doc.total <= account.balance + account.creditLimit;
  },
};
const orders = api.createRouter<Order, { canPlaceOrder: boolean }>(OrderModel, {
  operationAccess: { read: true },
  permissionSchema: { total: false, account: true, canPlaceOrder: true },
  virtuals: { canPlaceOrder },
});
```

The ref is automatically retained; there is no need for `dependsOn: ['account']`.
Use the authenticated server actor's tenant in real row hooks. Source/target input-field
`permissionSchema` is already bypassed by the declaration; the virtual's own output
authorization still applies. True requires captured **base read** admission; false skips
only that private operation guard. Both modes retain request-mode
`overrideFilter.read`/`baseFilter.read`, with source IDs ANDed after transforms.
There is no read-to-list fallback, route-variant gate or private `access` override.
Ordinary `populate.match`, `access`, selection and `authorization.related` cannot
redefine these inputs or grant private reads. A related policy for a dependency-only
path is unused/invalid. False-mode virtual-only output performs no operation check
solely to fetch private inputs; it grants no public field/operation, row or write authority.

Compatible public/private target queries fetch a normalized persisted union; the
original public selection and authorization stay separate and immutable:

- In **all four modes**, source unselection/exclusion/field denial omits the ref.
  There is no additional target-base-read reference-visibility gate. Adding a virtual
  does not change ordinary ref shape, including when private strict admission fails.
- With source selected/permitted, ordinary admitted
  `populate: [{ path: 'account', select: 'name -_id' }]` returns
  only `account.name`, even if private fetched fields are readable but unrequested.
- With source selected/permitted, no admitted ordinary population restores the exact original
  ID/array: missing IDs, order, duplicates, nulls, absence and empty arrays survive.
- An actual admitted population miss returns scalar null or a filtered array, never
  restored IDs. Private denial/row/query/getter failure or deferred virtual denial
  cannot hide otherwise permitted IDs or widen a public mask.

Resolved default population counts as ordinary; explicit `populate: []` suppresses
defaults. Public `-_id` exclusions survive private identity fetching. Cleanup runs
before output copying/handles and decorate/decorateAll/tasks, including on unavailable inputs, undefined/throw
and post-fetch virtual denial. No private maps/raw values are implicitly transported
to DTOs, hooks, handles or metadata; only the authorized getter's deliberate return
becomes computed output.

Declarations accept only `{ path, select? }`, no model/match/access/populate. `path`
must be a scope-local static string ref on an ObjectId scalar or 1D ObjectId array
to a registered ObjectId-identity model. Embedded virtuals declare the field in their
`.sub` scope, never a dotted root path. Dynamic/refPath/function/model-valued refs,
Map/Mixed, virtual populate, discriminator-varying scopes/targets, cross-connection
models, non-ObjectId IDs and multidimensional ref arrays reject explicitly.

`select` accepts comma/space strings, string arrays or **1/-1** objects (not 0).
Omitted/empty selects all eligible static stored fields; exclusion-only subtracts
from that catalog; negative paths win over positives. `_id` is supplied unless
excluded, while association identity stays privately fetched. Static embedded dotted
paths/containers expand to eligible stored leaves; target refs remain IDs, not traversed
objects. Explicit virtual/alias/unknown/unsafe/control/metadata/version/dynamic paths
and invalid exclusions/tokens reject. No recursive private target virtual computation
occurs; target service defaults/requireExplicitSelect do not replace this mask.

Per-access lists inherit independently of local `dependsOn`: exact getter then
default, bare getter inherits shared lists, defined leaf list replaces wholesale,
`[]` clears, undefined inherits, null rejects. Duplicate paths within one declaration
reject. Different getters may share a path but receive only their own isolated mask.

Support includes direct/root/trusted reads, writes/upserts, templates, ordinary
populated/included outputs, embedded scopes and visible dedicated subdocuments.
Writes capture post-lifecycle refs without changing saved refs/snapshots or retry
semantics; hidden rows run no getter. `new` ignores args.select and loads present
default refs under the captured private-read mode/request read-row scope without saving. Count/distinct/exists/delete identities
and include-count/field helpers add no dependency I/O. `SubPopulate` stays path/select-only.

Private reads inherit receiving hydration: direct read/populate mode, fixed lean for
includes and child mutation visibility, hydrated for dedicated child read/list and
ordinary writes/templates. Native values/defaults/getters/transforms can differ; exact
restoration refers to that captured materialized value, not cross-mode raw BSON equality.
Measured one-versus-24-row lists with two compatible target groups both used two target
finds (plus one parent find), at persistence/getter limits 1 and 2. Independent public
correlated queries remain per parent; no universal constant query count is promised.

See [Getter absence/error rules](./hooks#private-populated-getter-inputs) and the
[installed README's runnable example](https://www.npmjs.com/package/@web-ts-toolkit/access-router#private-populated-dependencies)
for the executable four-mode response shapes and breaking migration guidance.

## Operation Access

Use `OperationAccess` in `ModelRouterOptions.operationAccess` for all fourteen
model keys: `basicList`/`advancedList`, `basicRead`/`advancedRead`,
`basicCreate`/`advancedCreate`, `basicUpdate`/`advancedUpdate`,
`basicUpsert`/`advancedUpsert`, `basicCount`/`advancedCount`, and
`basicDistinct`/`advancedDistinct`. The [complete routing matrix](./routing#model-router-routes)
maps endpoints to these keys. Data routers use four list/read keys; subdocument
fields use four nested list/read keys.

An exact variant **replaces** the base guard. Only undefined inherits the existing
base exact → `operationAccess.default` → scalar `operationAccess` shorthand
resolution. False, an empty array, and a false-returning hook are final. With no
other fallback/default variant configured:

| Rules                              | Basic list | Advanced list | Root list entry |
| ---------------------------------- | ---------- | ------------- | --------------- |
| `list: true`                       | allowed    | allowed       | allowed         |
| `list: false`                      | denied     | denied        | denied          |
| `list: true, basicList: false`     | denied     | allowed       | allowed         |
| `list: true, advancedList: false`  | allowed    | denied        | allowed         |
| `list: false, basicList: true`     | allowed    | denied        | denied          |
| only `basicList: true`             | allowed    | denied        | denied          |
| `list: true, basicList: undefined` | allowed    | allowed       | allowed         |

<!-- doc-example: partial -->

```ts
import acl, { type ModelRouterOptions } from '@web-ts-toolkit/access-router';

const baseOnly = {
  operationAccess: { list: true, read: true },
  permissionSchema: { name: true },
} satisfies ModelRouterOptions;
const advancedReadsOnly = {
  basePath: '/users',
  operationAccess: { list: true, read: true, basicRead: false },
  permissionSchema: { name: true },
} satisfies ModelRouterOptions;
const basicListsOnly = {
  operationAccess: { list: true, advancedList: false },
} satisfies ModelRouterOptions;
const permissionBased = {
  operationAccess: { list: true, read: true, advancedList: 'isAdmin', advancedRead: ['canRead', 'isAdmin'] },
  permissionSchema: { name: { list: true, read: true } },
} satisfies ModelRouterOptions;
const shorthand = { operationAccess: 'canUseApi' } satisfies ModelRouterOptions;
const withDefault = {
  operationAccess: { default: 'canUseApi', list: true, basicRead: false },
} satisfies ModelRouterOptions;

acl.setDefaultModelOptions({ operationAccess: { list: true, read: true } });
acl.setDefaultModelOption('operationAccess.advancedRead', 'isAdmin');
const defaultRead = acl.getDefaultModelOption('operationAccess.advancedRead');
```

Among top-level model routes, `basicRead: false` denies only GET-by-id (and its HEAD fallback), leaving both
advanced read POSTs authorized by `read: true`. List/new/count/distinct/mutation
guards remain independent. Denial is **HTTP 401**, with endpoints still present
in `getEndpoints()` and OpenAPI.

Rule values are `Validation` (`boolean | string | string[] | GuardHook`). Strings
AND space-separated permissions; arrays OR their entries. Hooks receive
`AccessRouterPermissions`, bind `this` to the request, and may be async. Only the
selected guard runs; operational errors do not become permission fallback.
Configure permission names with `globalPermissions`. Field grants stay in
`PermissionSchema`/`FieldOperationAccess` under base names, not variant names.

### Model default specificity

Model exact variant lookup consults the runtime's same exact default path if the
model value is undefined, **before** base fallback. A default `advancedRead` can
therefore outrank a model's `read`, `default`, or shorthand; an exact model variant
outranks that default variant. A model object still replaces its stored
`operationAccess` object shallowly, rather than recursively inheriting all siblings.

Copied default values remain stored until updated. Later default setter calls do
not broadcast replacement over existing model values; clearing a stored variant
may expose the current exact runtime default. `getDefaultModelOption` reads a
path exactly, without variant/base or `.default` resolution.
`getDefaultModelOptions()` returns a frozen snapshot. Data routers have no model
default inheritance.

### Subdocument field rules

For `subs.comments.basicList`, precedence is exact field variant → field `list`
→ defined field scalar/closed object → top-level `basicList` **only for an absent
field** → existing top-level `list` fallback. Read/advanced variants follow the
same ordering.

<!-- doc-example: partial -->

```ts
import type { ModelRouterOptions } from '@web-ts-toolkit/access-router';

const options = {
  operationAccess: {
    list: true,
    read: true,
    subs: {
      comments: { list: true, read: true, basicList: false, advancedRead: 'isAdmin' },

      attachments: 'isAdmin',

```

A defined object without the applicable operation cannot be reopened by top-level
allows. Exact field lookups retain model-default specificity; an inherited defined
field also stays closed. There is no nested `.default` fallback. Legacy scalar `subs` rules remain
accepted, but do not act as an umbrella for absent fields; use explicit field rules.

Route grants retain base field/row/hook, root-entry, related-target, read-miss
fallback, upsert branch, and mutation-response policies. See [Services](./services#route-entry-and-service-policy).

## Request Complexity And Correlated Limits

`requestComplexity` bounds apply to every read/list/count request, including
correlated-include templates and their per-parent expansions:

- `maxDepth` (default `8`), `maxNodes` (default `500`),
  `maxLogicalClauses` (default `50`), `maxInValues` (default `100`),
  `maxBulkItems` (default `100`), `maxIncludeCount` (default `10`),
  `maxSubQueryCount` (default `10`), `maxBulkConcurrency` (default `10`),
  `maxHookConcurrency` (default `10`)
- `maxCorrelatedQueries` (default `100`): cumulative inner target executions per
  request/runtime (each executed per-parent read/list/count counts 1; nested levels
  multiply). Exceeding it fails the request/affected root entry.
- `maxCorrelatedDepth` (default `5`): nesting depth of correlated includes.

Each correlated entry counts toward `maxIncludeCount` and its markers count
as nodes; template `$in` lengths count toward `maxInValues`. After
per-parent substitution the expanded filter is revalidated against
`maxNodes`/`maxDepth`/`maxInValues`/`maxLogicalClauses`, so a short template
expanding against a large parent array can still be rejected. Prefer tight parent
filters and small per-parent limits to bound relationship work.

### Persistence admission

Both concurrency limits are normalized and captured together on first use of a
request/runtime's private work state. Existing owners retain that capture after
configuration changes; new requests capture the new limits.

`maxBulkConcurrency` bounds awaited adapter/document persistence operations across
model-service calls, root entries, subqueries, legacy includes and nested correlated
levels sharing one request/runtime. Each request and runtime has an independent pool;
services capture their runtime at construction. Admission awaits lazy queries,
save/delete and service-triggered post-write populate. Bulk create admits one
singleton-array adapter call per item, preserving result order and submitting every
item even if another rejects.

Recursive orchestration holds no permit while awaiting descendants, so limit `1`
supports nested includes. Internal map/run bounds remain per invocation.
`RootRouter.maxConcurrentOperations` separately limits whole root operations per
order group. Permits release on success/error with FIFO transfer; release does not
cancel submitted siblings or refund the cumulative correlated-query budget.

This is an adapter-operation ceiling, not a count of MongoDB driver commands: one
operation can issue multiple commands via Mongoose middleware/populate. Router ACL,
prepare, afterPersist and decorate run outside the permit; Mongoose middleware is
inside the awaited operation. Direct DB/network calls in trusted hooks are outside
admission. This is not a process-wide connection limit, transaction/optimistic-edit
guard or throughput guarantee. Controlled nested-query tests measured peak collection
calls falling from 9 to 3 at limit 3; that does not bound arbitrary middleware fan-out.

### Hook admission and nested service calls

`maxHookConcurrency` (default `10`) counts independent **hook chains** across one
request/runtime's services, root entries, includes, populate and subdocuments. The
pool covers model document-grant hooks (including pre-write/helper/owning-parent
stages), virtual getters, model/data `decorate`/`decorateAll`, service output
decorators and data request-field selection/trimming stages. Other guards, row/ID
filters, model field-rule callbacks and write lifecycle hooks are outside this pool.

A hook can await a nested service at limit `1`. Private async context lets its
descendant hooks reuse the chain, while each callback scope admits **one immediate
child branch at a time**, FIFO through descendant settlement. `Promise.all` sibling
hook stages therefore serialize rather than bypassing admission. Waiting ancestors
are additional frames, not additional permits: the limit bounds independent leaf
branches, not all unsettled callbacks. Reentrant depth is capped at 64 admission
scopes per chain, including internal wrappers; overflow uses the existing hook
failure policy. Settled scopes close to new reentry and drain queued children even
on failure; detached late continuations reacquire root admission. Await hook work
and avoid cross-branch dependency cycles. Root and child queues each transfer FIFO.

Row/traversal maps retain per-call worker limits and stable output/context order.
Hook and persistence pools are separate; no persistence permit is held over hooks
or orchestration. Trusted direct DB/network fan-out, total queued work and query
counts are outside these limits. They do not provide process-wide connection limits
or automatic N+1 batching.

## Data Router Options

Common data options:

- `data`
- `basePath`
- `operationAccess` supports `list`/`read`, `default`, scalar shorthand, and `basicList`/`advancedList`/`basicRead`/`advancedRead`
- `permissionSchema` maps fields to booleans, permission names, or per-operation rule objects
- `baseFilter`
- `overrideFilter`
- `decorate`
- `decorateAll`
- `requestSchemas`

Router-specific options:

- `listHardLimit`
- `idParam`
- `idField`
- `resolveIdFilter`
- `parentPath`
- `queryRouteSegment`
- `operationAccess`
- `dataName`

Set both `idParam` (Express parameter name) and `idField` (lookup field) explicitly
for data identifier routes; data has no model-default layer. Callable `resolveIdFilter`
takes precedence over `idField` for both model and data lookups. `parentPath` describes
an external mount prefix in metadata/logging; mount that prefix in Express yourself.

Data owns configured nested/native values and rejects unsupported values at assignment.
Services capture one dataset version and detach only selected/page-returned values.
Frozen snapshot native properties return detached mutable copies on access; native
identity is not stable. Replace through `router.data(next)` or runtime data setters.
See the installed README's “In-memory data ownership” for the exact supported values.

## Option APIs

The runtime exposes getter/setter pairs for each option group:

- `acl.setGlobalOptions(...)`, `acl.setGlobalOption(...)`, `acl.getGlobalOptions()`, `acl.getGlobalOption(...)`
- `acl.setModelOptions(...)`, `acl.setModelOption(...)`, `acl.getModelOptions()`, `acl.getModelOption(...)`
- `acl.setDefaultModelOptions(...)`, `acl.setDefaultModelOption(...)`, `acl.getDefaultModelOptions()`, `acl.getDefaultModelOption(...)`

Use router instance methods when you want to mutate one router in place.

<!-- doc-example: partial -->

```ts
import mongoose from 'mongoose';
import { createAccessRuntime } from '@web-ts-toolkit/access-router';

const runtime = createAccessRuntime();
const User = mongoose.model('ConfigurationVariantUser', new mongoose.Schema({ name: String }));
const router = runtime.createRouter(User, {
  basePath: '/users',
  operationAccess: { list: true, read: true },
  permissionSchema: { name: true },
});
router.operationAccess('basicRead', false); // Preserve the other keys.
router.operationAccess('subs.comments.basicRead', false);
router.set('operationAccess.advancedList', 'isAdmin');
router.setOption('operationAccess.basicRead', undefined); // Restore inheritance.
runtime.setModelOption(router.modelName, 'operationAccess.basicRead', false);

router.operationAccess({ list: true, read: true, basicRead: false }); // Whole rule replacement.
router.setOptions({ operationAccess: { list: true, advancedList: false } }); // Same shallow assignment.
const current = runtime.getModelOptions(router.modelName);
const exactVariant = runtime.runtime.getExactModelOption(router.modelName, 'operationAccess.basicRead');

const dataRouter = runtime.createDataRouter('VariantData', {
  idParam: 'id',
  data: [],
  operationAccess: { list: true, read: true },
});
dataRouter.setOption('operationAccess.basicRead', false);
dataRouter.runtime.setDataOption('VariantData', 'operationAccess.advancedRead', true);
const currentData = dataRouter.runtime.getDataOptions('VariantData');
```

`set({ operationAccess: ... })`, `setOption('operationAccess', ...)`, and property
helper object forms replace that entire object shallowly. Dotted paths are setter
arguments, not flat dotted properties in constructor options. A path update under
scalar shorthand starts an object; use `default` to retain the broad base fallback.
Use typed `set`/`setOption` with undefined to clear; property-helper key updates
are for defined values.

`router.options` is a frozen construction-time snapshot. Getter results are frozen
snapshots too (with data's native-copy behavior above); fetch again for current stored values. Generic
`getModelOption`/`getDataOption` use nested-option fallback, not route-specific
variant-to-base resolution. Exact getters expose the variant path (with exact model
default fallback); request guards resolve live runtime options.
